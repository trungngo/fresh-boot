A new machine, one command.

fresh-boot installs a small, sensible default set on a new Mac, Ubuntu desktop or server, or Windows PC, and lets you add anything else with one more command. It shows its plan before it changes anything, and it is safe to run again.

Why fresh-boot

Small by default. Yours to change.

A fresh install should not surprise you with forty apps you never asked for.

1

One command

The installer detects your platform, installs git, fetches this repository and dot, checks dot's download against its checksum, and applies the default set.

min

A small default

git, gh, glab, tailscale, zsh, tmux, vim and ghostty, wherever they exist for your platform. Languages, editors, apps and games are opt-in.

dry

Plan, then apply

dot plan shows every change first. dot status shows drift. Re-running dot apply changes nothing that is already right.

new

Always current

Nothing pins a version. Each installer resolves the current stable release when it runs, and dot apply --upgrade upgrades what is outdated.

key

No secrets inside

The repository holds no tokens, keys or personal data. Your name and e-mail are asked once and kept on your machine only; logins happen interactively.

fork

Opinionated, so fork it

The shell, tmux, vim and terminal configs are one person's taste. Fork the repository and edit dot.yml and the bundles until the result is yours.

What installs

The default, then whatever you add.

Every tool is a bundle: a directory with a manifest and a README that says what it installs and why.

  • Default: git gh glab tailscale zsh tmux vim ghostty, plus the baseline every bundle assumes.
  • Languages: nodejs python rust go java dotnet maven.
  • Dev tools: vscode docker zed jetbrains-toolbox claude codex.
  • Apps: chrome slack localsend libreoffice and more.
  • Platforms: macOS, Ubuntu desktop, Ubuntu server and Windows (the least tested).
$ dot apply nodejs python rust
$ dot apply vscode docker
$ dot apply claude codex

# which bundles exist, and in what order
$ dot graph

# why a bundle is (not) part of this machine
$ dot why docker
Use

Day to day.

fresh-boot is a repository of bundles, and dot is the tool that applies it. The checkout lives in ~/.dot.

  • Add software: dot apply <bundle> installs it with what it requires.
  • Keep current: dot apply --upgrade, and dot self-update for dot itself.
  • Check: dot plan changes nothing; dot status shows drift.
  • Change the setup: edit the checkout, commit and push; on another machine git pull, then dot apply.
  • Optional helper: tn, a small command for projects, git and tmux sessions.
$ dot apply              # converge this machine
$ dot apply --upgrade    # also upgrade what is outdated
$ dot apply docker       # one bundle, and what it needs
$ dot plan                # what would change
$ dot status              # drift and orphans
$ dot why docker         # why it is (not) installed
$ dot self-update        # newest dot release
Make it yours

Fork, edit, install.

Fork the repository, pick your set in dot.yml, change the bundles to taste, and point the installer at your fork with FRESH_BOOT_REPO. Every bundle's README explains what it does and why; CLAUDE.md holds the conventions for writing one.
